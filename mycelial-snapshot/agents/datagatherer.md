# Data Gatherer Agent – Mycelial Network

**Agent ID:** `datagatherer.mycelial`
**Type:** Data Acquisition & Intelligence Scout
**Status:** Active (Design Phase)

---

## 🧠 Purpose

This agent is the **sensory organ** of the mycelial network. It actively seeks out and retrieves data from external sources – APIs, websites, research repositories, and system updates – to feed the network with fresh, relevant information.

It does **not** analyze or validate data – that is the Security Agent's role. It only **acquires** and **stages** data for further processing.

---

## 🔧 Capabilities

| Capability | Description |
|------------|-------------|
| **API Fetching** | Pulls data from public APIs (weather, USDA, research, etc.) |
| **Web Scraping** | Extracts structured data from trusted websites |
| **Update Scanning** | Checks for system, software, and blocklist updates |
| **Data Staging** | Saves raw data to `~/mycelial/sources/` for validation |
| **Version Tracking** | Records timestamps and source metadata for each fetch |
| **Change Detection** | Compares new data with previous versions and flags changes |

---

## 📡 Update Detection

The Data Gatherer proactively scans for updates across multiple sources:

| Source | What It Checks | Hook / Method |
|--------|----------------|---------------|
| **Pi‑hole Gravity** | Blocklist count, last update timestamp | `check_updates.sh gravity` |
| **System Packages (apt)** | Number of available updates | `check_updates.sh apt` |
| **Python Packages (pip)** | Number of outdated packages | `check_updates.sh pip` |
| **Docker Images** | If `pihole-unbound` image has a newer version | `check_updates.sh docker` |
| **External APIs** | New data availability (USDA, weather, etc.) | `check_updates.sh external` |

All results are written to `~/mycelial/state/updates/` for the Boss agent to read and act upon.

---

## 🪝 Hooks (Validation Checkpoints)

| Hook | When | Purpose |
|------|------|---------|
| `pre_gather.sh` | Before any fetch | Validates the target source and ensures the network is ready |
| `post_gather.sh` | After a successful fetch | Logs results, updates state, and triggers Security Agent for scanning |
| `check_updates.sh` | Periodically (cron) | Scans for system, software, and blocklist updates |

---

## 📂 State File

Location: `~/mycelial/state/datagatherer.json`

Tracks:
- Last fetch timestamp and source.
- Hash of fetched data (for change detection).
- Update counts (apt, pip, gravity, docker).
- Pending update flags.

### Update State Directory

`~/mycelial/state/updates/` contains files generated by `check_updates.sh`:
- `pihole_gravity.txt`
- `apt.txt`
- `pip.txt`
- `docker.txt`
- `external.txt`
- `summary.txt`

---

## 🧪 Example Update Scan

1. **Cron triggers** `check_updates.sh all` at 6:00 AM daily.
2. **Data Gatherer**:
   - Checks Pi‑hole Gravity blocklist count and last update.
   - Scans for apt and pip updates.
   - Checks for new Docker image versions.
   - Records all results to `~/mycelial/state/updates/`.
3. **Boss agent** reads the summary and decides which updates to apply.

## 🔗 Relation to Other Agents
